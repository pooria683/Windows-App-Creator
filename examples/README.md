# Examples

Two real projects generated by the WinForge CLI and committed as living proof
that the templates work. **They are regenerated**, so don't edit them by hand —
change the template and run:

```bash
npm run build           # rebuild the CLI first
npm run create:example  # regenerate both projects
```

| Project | Template | What demonstrates |
| --- | --- | --- |
| [`electron-hello`](electron-hello) | Electron + React + TS | Secure preload/contextBridge, electron-builder NSIS + portable config, Windows cross-build from macOS/Linux |
| [`tauri-hello`](tauri-hello) | Tauri + React + TS | Rust command IPC, capabilities file, NSIS + WiX MSI bundle config |

## Try one

```bash
cd electron-hello
npm install
npm run dev             # hot reload (Vite + Electron)

npm run build:web       # renderer bundle
npm run build:main      # main process + preload
npx tsc --noEmit        # typecheck
npm test                # Vitest

npm run build:windows   # NSIS installer + portable .exe  (see note)
```

### Note on Windows builds from macOS/Linux

- **Electron** (`electron-hello`): `npm run build:windows` uses electron-builder,
  which cross-builds NSIS + portable `.exe` through Wine. The result is
  **unsigned** — SmartScreen will warn users. Wine is optional but recommended:
  `brew install --cask wine-stable` (macOS) or `sudo apt install wine` (Linux).
- **Tauri** (`tauri-hello`): `npm run build:windows` only works **on Windows**.
  Rust cannot cross-compile Windows binaries from macOS/Linux. Use the generated
  workflow (`winforge ci`) and the `windows-latest` runner.

Neither example's installers are production-ready until they are signed and
tested on the target OS. See `../docs/signing.md`.

## Environment variables for signing (all optional)

```bash
# Windows Authenticode
export WIN_CSC_LINK=/absolute/path/to/cert.pfx
export WIN_CSC_KEY_PASSWORD=…

# macOS notarization
export APPLE_ID=…
export APPLE_APP_SPECIFIC_PASSWORD=…
export APPLE_TEAM_ID=…
```

Nothing is set by default, and no secrets are committed.
